# बैकअप और बहाली

GPU इतिहास दो जगह रहता है जिनका साथ बैकअप लेना आवश्यक है: डेटाबेस रिकॉर्ड जो बताते हैं कि डेटा स्रोत किस GPU का है, और RRD फ़ाइलों में वास्तविक इतिहास (REQ-BACKUP-001)।

<a id="what-to-back-up"></a>
## किसका बैकअप लें

| सामग्री | स्थान | कारण |
|---|---|---|
| पूरा Cacti डेटाबेस | सभी `plugin_gpu_*` तालिकाएँ और `settings` की `gpu_*` पंक्तियाँ | नोड, UUID वाले GPU रिकॉर्ड, नवीनतम नमूने तथा GPU को RRD से जोड़ने वाले डेटा स्रोत, ग्राफ़ और क्वेरी कैश |
| RRD निर्देशिका | डिफ़ॉल्ट `<cacti>/rra` | इतिहास |
| प्लगइन सेटिंग | डेटाबेस डंप में `settings` तालिका की `gpu_*` पंक्तियाँ | *Mark Absent After*, *Stale After*, *Keep Plugin Tables on Uninstall* और स्कीमा संस्करण |
| हर नोड की `snmpd.conf` extend पंक्तियाँ | नोड पर | Cacti इन्हें बहाल नहीं करता; [node-setup.md](node-setup.md) से कॉपी करें |

डेटाबेस डंप और RRD प्रति एक ही समय लें, Cacti पोलर रोककर या चक्रों के बीच, ताकि कोई एक दूसरे से नया न हो। चालू डेटाबेस का सुसंगत डंप:

```
mysqldump --single-transaction --routines cacti > cacti.sql
```

<a id="restore"></a>
## बहाली

1. Cacti पोलर, उसकी cron प्रविष्टि या सेवा, रोकें।
2. डेटाबेस बहाल करें: `mysql cacti < cacti.sql`।
3. उसी बैकअप से RRD निर्देशिका बहाल करें।
4. पोलर शुरू करें। अगला संग्रह हर GPU को UUID से रिकॉर्ड के विरुद्ध जाँचता है, इसलिए उसका डेटा स्रोत और RRD फ़ाइल बनी रहती है और मान वहीं आगे जुड़ते हैं।

<a id="a-database-older-than-the-rrd-directory"></a>
## RRD निर्देशिका से पुराना डेटाबेस

यदि केवल डेटाबेस बहाल हो या डंप RRD फ़ाइलों से पुराना हो, तो Cacti डंप के समय वाले डेटा स्रोत ID फिर बाँटता है। RRD फ़ाइलों के नाम डेटा स्रोत ID पर होते हैं। बहाली के बाद पहली बार आने वाले GPU को ऐसा स्रोत मिल सकता है जिसका फ़ाइल नाम पहले से डिस्क पर दूसरी GPU का इतिहास रखता हो।

प्लगइन इसे रोकता है (REQ-BACKUP-003): GPU के लिए डेटा स्रोत बनाते समय उस पथ पर RRD फ़ाइल पहले से हो तो Cacti के लिखने से पहले उसका नाम `.gpu-orphan-<time>` प्रत्यय से बदलता है और डेटा स्रोत बताने वाली चेतावनी लॉग करता है। नया GPU अपना इतिहास शुरू करता है। पुरानी फ़ाइल रखी जाती है; उसका इतिहास चाहिए तो उसकी GPU पहचान जाँचकर सही डेटा स्रोत से हाथ से जोड़ें।

<a id="tested"></a>
## परीक्षण

`tests/bin/restore-flow.php` CI में `mysqldump` और `mysql` से वास्तविक `snmpd` के विरुद्ध दोनों मामले शुरू से अंत तक चलाता है:

- बदले हुए डेटाबेस, जिसमें एक GPU हट चुका था, पर डंप बहाल करने से बैकअप सूची वापस आती है और हर GPU अपना डेटा स्रोत तथा RRD फ़ाइल रखता है, जहाँ उसके अपने मान आगे जुड़ते हैं (REQ-BACKUP-002);
- चार GPU आने से पहले का डंप बहाल करके चार अलग GPU आने देने पर उन्हें ऐसे डेटा स्रोत मिलते हैं जिनके RRD नाम पहले से लिए हुए हैं। हर पुरानी फ़ाइल लिखने से पहले अलग रखी जाती है और हर नई फ़ाइल में केवल नए GPU के मान होते हैं।
