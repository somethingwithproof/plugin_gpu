# النسخ الاحتياطي والاستعادة

يوجد تاريخ GPU في موضعين يجب نسخهما معًا: سجلات قاعدة البيانات التي تحدد وحدة GPU التابعة لكل مصدر بيانات، والتاريخ نفسه في ملفات RRD (REQ-BACKUP-001).

<a id="what-to-back-up"></a>
## ما يجب نسخه احتياطيًا

| المحتوى | الموقع | السبب |
|---|---|---|
| قاعدة بيانات Cacti كاملة | تشمل جداول `plugin_gpu_*` وصفوف `settings` المسماة `gpu_*` | العقد وسجلات GPU حسب UUID وأحدث العينات ومصادر البيانات والرسوم وذاكرة الاستعلامات التي تربط كل GPU بملف RRD |
| دليل RRD | افتراضيًا `<cacti>/rra` | التاريخ |
| إعدادات الإضافة | صفوف `gpu_*` في جدول `settings` ضمن نسخة قاعدة البيانات | *Mark Absent After* و*Stale After* و*Keep Plugin Tables on Uninstall* وإصدار المخطط |
| أسطر extend في `snmpd.conf` لكل عقدة | على العقدة | ليست من مسؤولية Cacti للاستعادة؛ انسخها من [node-setup.md](node-setup.md) |

خذ نسخة قاعدة البيانات ونسخة RRD في الوقت نفسه، مع إيقاف المستطلِع أو بين دوراته، كي لا تكون إحداهما أحدث. لإنشاء نسخة متسقة من قاعدة بيانات عاملة:

```
mysqldump --single-transaction --routines cacti > cacti.sql
```

<a id="restore"></a>
## الاستعادة

1. أوقف مستطلِع Cacti، سواء مهمة cron أو الخدمة.
2. استعد قاعدة البيانات: `mysql cacti < cacti.sql`.
3. استعد دليل RRD من النسخة الاحتياطية نفسها.
4. شغّل المستطلِع. يفحص الجمع التالي كل GPU حسب UUID مقابل سجلاتها، فتحتفظ بمصدر البيانات وملف RRD وتستمر قيمها فيهما.

<a id="a-database-older-than-the-rrd-directory"></a>
## قاعدة بيانات أقدم من دليل RRD

إذا استُعيدت قاعدة البيانات فقط، أو كانت النسخة أقدم من ملفات RRD، يعيد Cacti توزيع معرّفات مصادر البيانات الموجودة وقت النسخ. ويسمي ملفات RRD بمعرّف المصدر. قد تحصل GPU تظهر لأول مرة بعد الاستعادة على مصدر ذي اسم ملف موجود أصلًا على القرص ويحوي تاريخ GPU أخرى.

تمنع الإضافة ذلك (REQ-BACKUP-003): عند إنشاء مصدر بيانات لـ GPU ووجود ملف RRD في مساره، تعيد تسميته باللاحقة `.gpu-orphan-<time>` قبل كتابة Cacti، وتسجل تحذيرًا يحدد المصدر. تبدأ GPU الجديدة تاريخها الخاص. يُحفظ الملف المعاد تسميته؛ إن احتجت إلى تاريخه، تحقق من GPU التي كان يتبعها ثم اربطه يدويًا بمصدر البيانات الصحيح.

<a id="tested"></a>
## ما اختُبر

يشغّل `tests/bin/restore-flow.php` الحالتين كاملتين في CI باستخدام `mysqldump` و`mysql` مع `snmpd` حقيقي:

- تستعيد استعادة النسخة فوق قاعدة تغيرت بعد حذف GPU الجرد المحفوظ، وتحتفظ كل GPU بمصدرها وملف RRD وتستمر قيمها الخاصة فيه (REQ-BACKUP-002)؛
- عند استعادة نسخة أُخذت قبل وجود أربع وحدات GPU، ثم ظهور أربع وحدات مختلفة، تحصل الوحدات الجديدة على مصادر بأسماء ملفات RRD مستخدمة. يُنقل كل ملف موجود جانبًا قبل الكتابة، ولا يحتوي كل ملف جديد إلا قيم GPU الجديدة التابعة له.
