# Cacti core behavior

Research for [#24](https://github.com/somethingwithproof/plugin_gpu/issues/24), 2026-11-15. Question: does each Cacti function, hook, and table behavior the plan relies on hold at `release/1.2.31` and on the current `1.2.x` branch?

**Result.** Every function the plan names exists with the same signature at both refs, and every hook the plan uses has a call site at both refs. The plan's data query rows hold (the `resource/` confinement, orphan handling, reindex method None, script server containment). Five statements needed correction or sharpening: (1) the reindex method is reset by `api_device_update_host_template()`, not by `api_device_save()`; (2) `run_data_query()` returns without reindexing when the device is down or disabled; (3) a data query can set `index_transient`, which stops removed indexes being marked orphan at all and is a better fit than relying on the absence of `index_orphan_removal`; (4) `poller_bottom` on a remote collector needs the `remote_poller` capability, which the plan's metadata paragraph does not name; (5) data source item names are limited to 19 characters, and two throttle names the plan might use exceed it. Nothing was run. All rows come from `git show` and `git grep` of the two refs. Findings that the plugin_cloud research already established were re-checked here and are marked.

## Limits

- Nothing was executed. In particular the claim that a script server data query works on a device with availability None was run in the plugin_cloud research at 1.2.31 with PHP 8.0.30; it was not repeated.
- Line numbers at B for `utility.php` were not compared individually; the function exists at both refs (R 173, B located by name).
- Thold, Maint, and Spine were not run. Spine is not used by this plan's design.
- The `release/1.2.31` tag object and the `1.2.x` branch are other sessions' worktrees; they were read with `git show`, `git grep`, and `git rev-parse` only.
